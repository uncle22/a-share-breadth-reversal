# 指标口径详解

本文说明 `scripts/breadth.py` 里每个数字的**确切定义**、**边界处理**和**易错点**。
如果你要改代码或自己复现，先读这份。

---

## 0. 样本池

```
fs = m:0+t:6   深市主板
     m:0+t:80  创业板
     m:1+t:2   沪市主板
     m:1+t:23  科创板
```

**不含北交所、不含 B 股、不含新三板。**

实测总数约 **5,565 只**（2026-11），其中当日有成交的「有效家数」约 5,200。

> **为什么不剔除 ST？**
> ST 会涨跌停，会扭曲 TRIN 的分子分母。但剔除后「有效家数」会随 ST 名单变化，
> 反而让「涨家占比」失去时间可比性。
> **折中方案**：保留在样本里，但**涨跌停阈值按 4.8% 单独判定**（见 §5）。

## 1. 涨家占比

```
涨家占比 = 上涨家数 / (上涨 + 下跌 + 平盘)
```

**边界**：

- 平盘计入分母，不计入分子
- 停牌股不在快照里，天然排除

| 阈值 | 含义 |
|---|---|
| ≥ 60% | 普涨 |
| 40–60% | 中性 |
| < 40% | 普跌 |
| **< 25%** | **极端分化，触发报警** |

---

## 2. 涨额占比 / 涨量占比

```
涨额占比 = 上涨股成交额之和 / 全部成交额之和
涨量占比 = 上涨股成交量之和 / 全部成交量之和
```

**注意**：分母是**全部**（含平盘股），不是「涨+跌」。
平盘股虽然家数少（约 100–150 只），但可能是有大额成交的停牌复牌股。

---

## 3. 额价差 / 量价差

```
额价差 = 涨额占比 − 涨家占比   （单位：百分点 pp）
量价差 = 涨量占比 − 涨家占比
```

**这是本项目最核心的「抱团探测器」。**

### 直觉

设想 100 只股票，30 只涨：

| 场景 | 涨额占比 | 额价差 | 含义 |
|---|---|---|---|
| 30 只涨，占 30% 成交额 | 30% | **0pp** | 涨的股票「平均大小」正常 → 普惠 |
| 30 只涨，占 45% 成交额 | 45% | **+15pp** | 涨的是大票 → **权重拉指数** |
| 30 只涨，占 20% 成交额 | 20% | **−10pp** | 涨的是小票 → 题材扩散 |

| 阈值 | 判分 |
|---|---|
| ≤ 4pp | 2 分（普惠） |
| 4–10pp | 1 分（偏抱团） |
| > 10pp | 0 分（强抱团） |

> **负的额价差（小票在涨）也是 2 分** —— 因为那代表「广度在扩散」，
> 对散户持有的中小盘更友好。

## 4. TRIN（Arms Index / 阿姆氏指标）

### 定义

1967 年 Richard W. Arms Jr. 提出，原名 **TRIN**（TRading INdex）。

```
TRIN = (上涨家数 / 下跌家数) ÷ (上涨成交量 / 下跌成交量)

等价形式：
TRIN = (上涨家数 × 下跌成交量) ÷ (下跌家数 × 上涨成交量)
```

本脚本同时算两个版本：

| 变量 | 分母用 | 对谁敏感 |
|---|---|---|
| `trin_amt` | 成交额（元） | **高价股** |
| `trin_vol` | 成交量（股/手） | **低价股** |

### 「倍数」翻译（最好懂）

```
每只上涨股的平均成交额 ÷ 每只下跌股的平均成交额 = 1 / TRIN
```

| TRIN | 倍数 | 含义 |
|---|---|---|
| 0.35 | **2.9×** | 上涨股拿到的钱是下跌股的 2.9 倍 |
| 0.50 | 2.0× | 2 倍 |
| 1.00 | 1.0× | 公平分配 |
| 2.00 | 0.5× | 下跌股拿到的钱是上涨股的 2 倍 |

### ⚠️ 必须结合涨家占比（本项目的关键修正）

**TRIN 是「比值的比值」，脱离语境会误判。**

| 场景 | TRIN = 0.35 的含义 | 判分 |
|---|---|---|
| 涨家 **70%**（普涨） | 资金坚决做多 | **2 分** |
| 涨家 **16%**（普跌） | **极端抱团**，少数票吸金 | **1 分** |

**实现（`score_all` 里的分支）**：

```python
if up_ratio >= 0.55:          # 普涨：低 TRIN 是好事
    t <= 0.70 → 2分
    t <= 1.00 → 1分
    else      → 0分
else:                          # 普跌：低 TRIN 是抱团警示
    t <= 0.50 → 1分
    t <= 1.20 → 1分
    else      → 0分（资金全面撤离）
```

### Arms 本人的极值用法（本版本未启用）

| 数值 | Arms 的解释 |
|---|---|
| 单日 TRIN > 3.0 | 恐慌抛售，常是短期底 |
| 单日 TRIN < 0.5 | 过热 / 拥挤 |
| 10 日均 TRIN < 0.8 | 超买 |
| 10 日均 TRIN > 1.2 | 超卖 |

> **「TRIN 极高」在 Arms 的框架里反而是底。**
> 本版本没启用极值反转逻辑，因为 A 股的 TRIN 分布与纽交所不同，
> 阈值需要重新标定（见 `limitations.md` §4）。

### TRIN_额 vs TRIN_量 的差值 = 市值方向

```
TRIN_额 < TRIN_量  →  上涨股平均股价更高  →  大票在涨
TRIN_额 > TRIN_量  →  上涨股平均股价更低  →  小票在涨
```

**实盘例子（2026-11-18 11:46）**：

| | 数值 |
|---|---|
| TRIN_额 | 0.35 |
| TRIN_量 | 0.43 |
| 关系 | 额 < 量 |
| 结论 | **大票在涨** |
| 验证 | 科创50 +0.48%，上证 −0.40% ✅ |

## 5. 涨停 / 跌停

**A 股不同板块的涨跌停幅度不同，必须分开判定：**

| 板块 | 代码前缀 | 阈值 |
|---|---|---|
| 沪市主板 | 60 | ±9.7% |
| 深市主板 | 00 | ±9.7% |
| 创业板 | 30 | ±19.5% |
| 科创板 | 68 | ±19.5% |
| **ST 股** | 名称含 ST | **±4.8%** |

**为什么用 9.7% 而不是 10%？**
四舍五入会让「涨停价」对应 9.98%~10.02%，用 9.7% 留出容差，避免漏计。

**为什么不精确算涨停价？**
需要每只股票的前收盘价 + 板块规则 + ST 标记，东财快照不直接给涨停价。
用涨跌幅阈值是工程折中，误差约 ±2%。

## 6. 成交额 / 5 日均（含盘中归一化）

### 问题

11:00 的累计成交额 ≠ 全天成交额。直接和「5 日全天均值」比，会得出「缩量」的荒谬结论。

### 解决：按交易进度归一化

```
交易进度 progress =
    0                          t ≤ 09:30
    (t − 09:30) / 240          09:30 < t ≤ 11:30
    0.5                        11:30 < t ≤ 13:00
    (120 + t − 13:00) / 240    13:00 < t ≤ 15:00
    1.0                        t > 15:00

全天等效成交额 = 盘中累计成交额 / progress
放量倍数 = 全天等效 / 5日均
```

**这个折算假设「成交在时间上均匀分布」——现实中是 U 型（开盘尾盘高）。**

所以：

| 时间 | 折算偏差 |
|---|---|
| 10:00 前 | 高估（实际开盘放量，progress 偏低） |
| 11:00–13:00 | 接近 |
| 14:45 后 | **最准**（progress > 0.94） |

脚本在报告里明确标注：`⚠ 盘中数据：量能按交易进度线性折算，误差约 ±10%；14:45 后最准。`

### 历史记录污染问题

如果把盘中记录也写进 5 日均基准，基准会永久偏低。

**解决**：`full_day_avg()` 只取 `progress ≥ 0.99` 的记录：

```python
def full_day_avg(hist, n=5):
    vals = [h["amount_yi"] for h in hist
            if h.get("progress", 1.0) >= 0.99 and h.get("amount_yi")]
    return sum(vals[-n:]) / len(vals[-n:]) if vals else None
```

## 7. 历史分位 P20 / P60 / P250

```
pctile(value, series) = 100 × count(series < value) / len(series)
```

| 参数 | 窗口 |
|---|---|
| P20 | 近 20 条记录 |
| P60 | 近 60 条 |
| P250 | 近 250 条（≈ 一年） |

**样本门槛**：`len(series) >= 5`，否则返回 `None`。

**注意**：本项目的「分位」是**自身历史的分位**，不是「行业分位」，也不是「绝对水平」。
新装的用户前 5 天看不到分位，这是设计上的诚实，不是 bug。

## 8. 连续性

```
streak = 涨家占比「连续上升」的天数
```

**实现**：

```python
if today.up_ratio > yesterday.up_ratio:
    streak = 2 if yesterday.up_ratio > day_before.up_ratio else 1
else:
    streak = 0
```

| streak | 判分 |
|---|---|
| ≥ 2 | 2 分 |
| 1 | 1 分 |
| 0 | 0 分 |

> **「一天普涨」和「连续两天普涨」是完全不同的信号。**
> 前者是脉冲，后者才可能是反转。

## 9. 极致分化报警

```
if 涨家占比 < 25% and 额价差 > 15pp:
    报警：指数被少数权重/题材拉着，多数股票在跌
```

**为什么单列这一条？**

因为此时「指数红」和「账户红」是反的。用户看到指数涨会误以为行情好，
但实际上手里 70% 的仓位在跌。

**这是本项目对散户最有用的一条输出。**

## 11. 趋势指标（v0.2 新增）

### 11.1 10 日 TRIN 均线

```
trin_ma10 = mean(最后 10 条历史的 trin_amt)
```

| 阈值 | Arms 的解释 |
|---|---|
| **< 0.8** | 超买 |
| **0.8 – 1.2** | 中性 |
| **> 1.2** | 超卖 |

**为什么需要它**：单日 TRIN 的噪音极大（尾盘 30 分钟就能从 0.6 冲到 1.1），
10 日均才反映「资金分配的中期倾向」。这是 Arms 本人的核心用法。

**样本要求**：10 条历史记录。不足时返回 `None`，脚本明确提示「样本不足」，不编造。

### 11.2 MCL（McClellan Oscillator）

**公开定义**（Sherman & Marian McClellan, 1969）：

```
AD_t  = 上涨家数 − 下跌家数          （每日腾落值）
MCL   = EMA19(AD) − EMA39(AD)
```

**EMA 的递归写法**（与本脚本一致）：

```
k = 2 / (n + 1)
EMA_n 初值 = 前 n 个的简单平均
EMA_n(t) = AD_t × k + EMA_n(t−1) × (1 − k)
```

| 数值 | 含义 |
|---|---|
| **MCL > 0** | 短期广度强于长期广度 → 广度在改善 |
| **MCL < 0** | 短期广度弱于长期广度 → 广度在恶化 |
| **MCL 由负转正** | 经典的「广度转强」信号 |
| **MCL 极负（如 < −200）** | 广度已极度恶化，接近「恐慌」区间 |

**注意**：MCL 是**广度动量**，不是「超买超卖」。它的绝对值大小与市场家数规模有关，
所以 **A 股的 MCL 阈值不能照搬美股**（美股常用 ±70 做超买超卖）。

**样本要求**：39 条 AD 记录（因为 EMA39 需要至少 39 个点）。

### 11.3 为什么这两个都「要等历史」

它们都是**时间序列指标**，没有历史就没有值。

首次安装的用户会看到：

```
【七、趋势指标】
  10日 TRIN  样本不足（需 10 天，现有 1 天）
  MCL        样本不足（需 39 天，现有 1 天）
```

**这是诚实，不是 bug。** 想立刻看到值，只能自己回补历史（本脚本不提供回补，因为
历史「涨跌家数」没有免费的全量接口）。

## 12. 两票制（v0.2 新增）

**结论层**，不属于指标，但依赖上面所有指标。

### 12.1 资金面票

```
total <= 4   → 空
total <= 8   → 中
total >= 9   → 多
```

`total` 是六项打分的总分（0–12）。

### 12.2 技术面票

基于**上证日线**：

```
s = 过去收盘价（不含今日） + [今日现价]
MA5, MA10, MA20 = 对 s 求均

if 现价 > MA20 and MA5 > MA10:  多
elif 现价 < MA20 and MA5 < MA10: 空
else:                            中
```

**为什么用「现价」而不是「收盘价」**：盘中运行时，今日 K 线还没收，
用现价代替今日收盘，得到「当前时点的日线状态」。

**数据源**：腾讯日线 `web.ifzq.gtimg.cn/appstock/app/fqkline/get`（前复权）。

### 12.3 合并

```python
if fund == tech:
    return fund, "同向"
if fund == "中":
    return tech, "跟随技术面"
if tech == "中":
    return fund, "跟随资金面"
# 冲突
wait_side = "空" if fund == "空" else "多"
return "等", f"冲突 → 准备{wait_side}，等两边同向"
```

| 组合 | 输出 | 动作 |
|---|---|---|
| 多 + 多 | 多 | 可加/持有 |
| 空 + 空 | 空 | 不加，占比高的减 |
| 多 + 空 | **等（准备空）** | **不开新仓** |
| 空 + 多 | **等（准备多）** | **不开新仓** |
| 中 + 多 | 多（跟随） | 弱多 |
| 中 + 空 | 空（跟随） | 弱空 |

> **「等」是这套系统里唯一「允许你不做事」的状态。**
> 对高频操作者的价值，远大于任何指标。
